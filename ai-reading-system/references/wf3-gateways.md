# WF3 · 校验收尾与数据维护

> 读后收尾：一条命令完成「校验网关 → 页码注入 → 数据提取」。这是质量的最后一道闸。附数据日常维护与事故恢复。

## 一键执行

```bash
cd <工作目录>

# 0. 前置：工作台有改动时，先导出落盘
#    工作台点「导出」得到 json，然后：
node <技能目录>/scripts/save-export.js <导出的.json> --state data/state.js

# 1. 先 dry-run 看校验结果，不写盘
node <技能目录>/scripts/pipeline.js <书名> --data .

# 2. 通过后真实执行
node <技能目录>/scripts/pipeline.js <书名> --data .
```

管线内部三步（自动串联）：

1. **原文校验网关**：金句逐字回原文匹配（硬网关，未命中即退出）；案例做锚点匹配（软网关，定位不到的列入人工复核清单，留痕不静默）
2. **页码计算注入**：按全文 `[第 N 页]` 标记建索引，金句/案例缺页码的自动注入，直接写回 `data/state.js`（写前自动备份，幂等）
3. **提取单书数据**：`data/state-<书id>.json`（供备份/再加工）

可用参数：`--fulltext <md>` 指定原文路径；`--skip-verify` 跳过金句硬网关（救急）；`--dry-run` 只校验不写盘。

## 校验网关分级原理（为什么金句硬、案例软）

- **金句是引用**，读者会当原文转述，编造即事故 → 逐字匹配，未命中打回。
- **案例名是概括标签**（"买保时捷的讲座学员"原文是"我买了一辆保时捷"），逐字匹配天然不适用 → 锚点匹配名称或描述中 ≥6 字片段；定位不到 ≠ 编造（可能是忠实转述），列人工复核清单由人判断。
- 复核清单处理：逐条对照原文确认忠实性，确认后重跑管线自动通过（锚点已在文中）。

## 验收清单

- [ ] dry-run 报告：金句命中 100%，复核清单已逐条人工确认
- [ ] 真实执行三步全绿
- [ ] 页码抽查：金句/案例的 （P页） 与原文位置一致（EPUB 来源则确认"无页码"如实标注）

## 踩坑

- 全文 md 无页码标记时网关只报"无法定位"，不会编页码——EPUB 属正常；PDF 来源缺标记则回 WF1 修全文。
- 弯引号金句内嵌内层引号可能截断提取——网关已做分层提取，若见误报优先检查引号形态。
- 金句未命中多数是转写错字或 AI 改写了原句——回环节3修正，不要用 `--skip-verify` 掩盖。

## 数据维护与事故恢复

**数据分层**：`data/state.js` 是唯一真相；localStorage 只是浏览器缓存（自带 `_bak1~3` 滚动备份）；`data/state-<书id>.json` 是管线提取产物。

**日常习惯**（每完成 1-2 个环节）：工作台「导出」→ save-export 落盘（写前自动备份）。**不要**把工作台当持久存储——浏览器清缓存就没了。

**事故恢复**：

| 场景 | 处置 |
|---|---|
| 工作台里改坏了（未导出） | 关工作台别再点保存；从 localStorage `_bak1` 取 JSON 存文件 → save-export 回填 |
| state.js 被改坏/误删 | 找最近的 `state.js.bak-<时间戳>` 复原；再不行从 `data/state-<书id>.json` 反推 |
| 浏览器脏数据 | 工作台会自动用 state.js 重播种；仍异常则清 localStorage 后刷新 |

**改脚本/改工作台的规矩**：先备份 → 写盘前先跑通 dry 逻辑 → 改完跑验证 → 锚点匹配带足上下文（防止误删其他书的数据）。
